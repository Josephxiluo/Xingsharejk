# 药品保险报销活动福利平台后台 DEMO 规划

## 本期 DEMO 范围

本期仅实现 PC 运营后台的静态前端页面，用于客户确认后台信息架构、页面模块与核心业务流程，不涉及接口联调、数据库、真实文件上传、真实导入导出或支付打款能力。

## 页面信息架构

1. **运营总览**：展示活动总数、报名申请、理赔订单、已完成打款金额等指标，帮助运营人员快速了解当前业务状态。
2. **活动管理**：覆盖活动新增/编辑、活动状态、活动时间、图文内容、二维码生成入口，并支持按项目配置入组申请表单、理赔申请表单、入组协议与理赔申请协议。
3. **报名申请管理**：覆盖活动名称、用户姓名、手机号、审核状态、提交时间等筛选条件，以及用户资料查看、审核通过、审核拒绝、拒绝原因与 Excel 导出入口。
4. **理赔申请管理**：覆盖理赔状态看板、理赔资料查看、受理、驳回、修改状态、打款申请导出等运营动作。
5. **打款批处理**：体现“平台不自动打款”的项目边界，支持待打款订单导出、保险公司线下处理、批量导入打款结果的流程展示。
6. **会员管理**：展示用户昵称、手机号、注册时间、活动参与记录、理赔订单记录与资料上传记录。
7. **合作药房管理**：维护药房名称、地址、联系电话、地图坐标与活动关联配置。
8. **一键热线管理**：维护客服电话、企业微信客服说明与企业微信二维码展示位。
9. **运营账号与权限管理**：展示超级管理员、审核专员、客服运营等角色权限边界。

## 业务流程呈现

```text
活动创建/配置协议/生成二维码
        ↓
用户扫码进入小程序并提交报名资料
        ↓
后台人工审核报名申请
        ↓
审核通过后用户提交理赔资料
        ↓
后台人工审核理赔申请并维护状态
        ↓
导出待打款申请单给保险公司线下处理
        ↓
批量导入打款结果并更新订单状态
```


## 当前完成状态

已完成需求文档中 PC 运营后台部分的静态页面 DEMO 搭建，包括活动管理、报名审核、理赔审核、会员管理、数据导出入口、打款状态管理、合作药房管理、一键热线管理、账号权限管理等模块；活动管理中补充了按项目配置入组申请表单、理赔申请表单、入组协议和理赔申请协议的演示区域。

预览入口为项目根目录的 `index.html`，推荐通过 `python3 -m http.server 4173` 启动本地静态服务后访问 `http://127.0.0.1:4173/index.html`。


## 表单与协议配置说明

- 入组申请表单支持按活动项目配置字段，DEMO 展示了文本、下拉选择框、图片上传三类常用字段。
- 理赔申请表单支持按活动项目配置字段，DEMO 展示了药品名称、购买药房、发票/小票、银行卡信息等字段。
- 图片上传区域提供上传示例卡片，用于客户确认小程序端需要展示的凭证上传入口。
- 入组协议与理赔申请协议均支持多份自定义协议文件，后续正式开发时可扩展为 PDF/图片上传、排序、启停用和用户勾选确认记录。

## DEMO 交付文件

- `index.html`：后台运营 DEMO 主页面。
- `assets/styles.css`：Fily Admin 风格的后台布局、卡片、表格、表单与响应式样式。
- `assets/app.js`：侧边栏滚动定位高亮交互。
